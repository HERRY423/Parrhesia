# 作者负担与质量收益试评准备

状态：**仅完成工程工具与试验准备；真实材料、作者、模型调用和盲评均未运行。** 本方案专门区分“引擎能力不足”和“完整 L2 的填表、补错、上下文交接成本已抵消收益”。不把字节压缩、合成案例通过或记录字段齐全当作作者收益。

## 四组比较与决策

| 组别 | 操作 | 主要比较 |
| --- | --- | --- |
| `B_compact` | 同模型、同资料、相同原生工具能力，使用精简规则；无需结构化台账和角色编排 | 当前简化方案基线 |
| `S_prefill_single` | 同样的摄入、预填和台账；单上下文完成双向检查与最终文字判断，明确非独立审查 | 相对 B：结构化辅助本身是否值得 |
| `E_manual` | 完整 L2，人工/模型拼装台账，独立角色包与裁定 | 相对 E-prefill：填表负担来自哪里 |
| `E_prefill` | 完整 L2，显式选取来源行进行预填，检查遗漏、未知和冲突，再双审裁定 | 相对 S：跨上下文步骤是否有额外净收益 |

S 组不伪造多个审查身份，不绕过引擎门控，也不宣称完成完整 L2。所有组收到同一问题、原始证据和 3–5 条核心主张；最终盲评只看标准化文字输出与证据，不以“有没有生成台账/报告”决定科学质量。

关键比较均有明确后果：

- E-prefill 若比 E-manual 降低实际准备/纠错时间，且质量不劣，才支持预填降低负担。序列化字节更少只说明接口输入更短。
- E-prefill 若未比 S 提高质量，或提高不足以补偿额外时间，应优先单上下文辅助，把完整 L2 限定于争议案例。
- S 若与 B 相当且更费时，应优先精简规则；不能用“机械检查更多”作为默认完整流程的理由。
- 严重证据错误增加时先停止该路径试用；平均写作评分不能抵消捏造、误升级或掩盖反证。

## 计划边界与混杂控制

准备工具默认产生 **12 个来源案例槽位 × 4 组 = 48 个计划运行槽位**。这是可执行性试评的计划，不是已经选入的案例或功效证明。默认种子 `20261117`、轮换顺序可复现；顺序在四组间平衡。旧 Stage 0 四组、已暴露的保留集及这里的作者试评分别记录，不合并成一个总分。

开始真实试评前补齐：授权材料范围与数据去向、案例纳入/排除规则、作者及盲评者分配、已核实模型路由、各组相同的总 token/时间/费用上限，以及主要比较的质量非劣界值、最小有意义时间节省、严重错误容许增量。当前这些决策阈值是 `null`；不能称为已冻结的正式确证研究。小试评只用于估计可执行性和方差，后续正式样本量须另立版本，不能用有利结果倒推门槛。

每个来源案例各组配对，但同一作者不得在不同组反复看到同一材料；按作者、任务类别和顺序平衡，报告作者熟练度、材料长度和学习/疲劳效应。保持模型/版本、原始信息、工具能力及总预算可比；完整流程的多次审查和裁定都计入该组总预算。单次调用上限不是跨组等预算的替代。

盲评者不得评自己的输出。隐藏处理组、调试轨迹和成本，将输出格式归一化，再锁定质量评分；保留评分分歧和无法判定。独立性是待核查的运行事实，不能由不同 context_id 自动证明。

## 需要记录的结果

质量：夸大、低估、已支持贡献保留、严重证据错误、完整性，以及同时满足这些要求的联合质量。未知或无可判定参照时不强填通过。

负担：活跃操作时间、其中的填表/修正时间、补错次数、跨上下文交接次数、总输入/输出 tokens、费用、失败步骤、放弃/取消/超时；准备、重试和最终修复均计入。墙钟等待与人的活跃时间分开，不用脚本运行秒数代替作者时间。作者自报时间和宿主日志分别保留来源，不能互称已认证。

统计单位是来源案例；重复模型采样不增加独立案例数。正式分析按案例/作者聚类，报告配对差值及区间；主要比较与多重性策略在看结果前固定。这里的汇总器只作带缺失分母的描述，不自动输出疗效式显著性、采用率或 `user_impact` 通过结论。

## 可执行准备与记录

```powershell
python -X utf8 scripts/prepare-impact-pilot.py prepare --output review/my-author-pilot
python -X utf8 scripts/prepare-impact-pilot.py summarize --plan review/my-author-pilot
```

输出 `protocol.json`、带指纹的 `assignments.jsonl`、`observation-template.json`、四组任务提示和 `BLINDED-RUBRIC.md`。准备目录必须不存在，避免覆盖上一版本。当前没有观测时汇总状态为 `not_run`，费用、时间和质量均为 `null`。

获准执行后，每个运行保留一条最终观察记录，保存为 JSONL，并附原始时间戳、宿主调用回执和来源文件摘要；途中失败也记录，不能只留下成功记录。用新的文件保存修订，不覆盖既有原始记录。示例：

```powershell
python -X utf8 scripts/prepare-impact-pilot.py summarize --plan review/my-author-pilot --observations review/my-author-pilot/observations.jsonl
```

汇总器核对计划/分配内容、重复或未知 run_id、非法数值及状态；拒绝将未完成输出写成已完成评分。缺失记录仍留在分配分母中；真实的 0 与未知分开。所有表单均注明 caller-reported，不能由自报字段认证宿主调用、作者独立性或科学有效。

使用 `--benchmark` 绑定材料时，已完成观测的 `material_sha256` 必须与分配一致。加载材料前失败的记录可以保留未知材料指纹，仍计入对应失败状态。摘要匹配校验报告与分配相符，实际送达内容仍应由宿主回执核对。

开始外部调用前须恢复历史费用记录，核对实际模型路由及可执行费用上限。过去 Claude CLI 的预算停止参数曾超额，因此不能把该参数或本地记录当作硬上限。这里的工具没有模型执行入口；材料、授权、费用控制未就绪时只保留准备状态。

## 停止与收敛

不自动启动真实试评、不自动补样本、不重置累计预算。达到预先约定的案例/时间/token/费用边界即停止；保存失败、取消、阴性和无法判定结果。若简化方案已经满足质量且持续更省时，应收窄完整 L2 的适用范围，而不是继续增加填表字段或追求更多拦截规则。
