## 两次误提示如何修复

- **附带安全性结果污染疗效主张**：原逻辑依赖有限的疗效词表，未识别具体端点时把安全性无差异算作反证。现在依据当前主张的端点词及既有主要结果线索，对单独安全句限定作用范围；安全性本身是主张、混合主张、显式主要安全终点或同句包含目标端点时保留提示。孤立安全句和缺乏端点信息的主张不会因缺少上下文而被自动丢弃。
- **历史批评污染当前研究**：对明确指向既往研究的对比从句，仅在存在当前研究上下文且从句不混入当前结果时排除。当前研究失败、没有清晰分句或上下文不完整时保留检查。来源中已出现的原文引文继承已读取的来源上下文，避免被单独再扫而复活误提示。

另补交付前边界反例：不同句/行的 `no` 与 `Support` 不能拼成否定词组；扫描时保留句间分隔。原误触发记录与针对性测试一并保存。

实现位于 `parrhesia/text_advisories.py`，仅供提示层与非阻断对称性审计使用。`text_anchors.py` 原字节不变；数值锚定、结构化效应、设计门控与冻结状态不放宽。没有按旧案例 ID 或复制其完整句子设规则。静态常量检查不能证明不存在过拟合，因此新正反例与边界限制同样保留。

## 改判条件与下一步

本轮支持的只是有限案例上的工程修复。若新增有效正对照受到误提示，或主要安全/当前失败被消音，应收窄对应范围规则；不得以提高召回为由容忍未说明的误报。剩余四类要升级为可靠检查，需要先补齐直接效应、识别设计或数据划分证据，并让新的正反对照同时通过。

下一步可直接运行新提示层入口与 Stage 0 回归，将新增材料保存为独立版本再测试；未暴露、由其他来源编写的测试集才能进一步检验泛化。真实作者收益试评仍维持“准备完成、尚无观测”，当前结果不升级到 `host_accepted` 或 `user_impact`。
