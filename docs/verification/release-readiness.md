最终测试命令为 `python -m unittest discover -s tests -v`。Windows 沙箱拒绝对新建目录执行严格路径解析；同一探针在获准的本地进程通过。测试使用项目内 TEMP/TMP 并在该本地环境执行，未为使测试通过而移除路径保护。符号链接创建检查因当前 Windows 账户没有创建权限而跳过，不能报告为通过；路径越界、设备名与内部状态目录拒绝测试已通过。

独立审阅修复了：①先暂停再质疑/暂缓会意外恢复写入；现在暂停持续到明确接受，暂停也不能首次创建裁决包。②HTML 未显示条件性判定/部分采纳的 condition；现在原样转义展示。另修正演示的判定语义：收窄后的相关命题获支持，不代表原稿因果命题获支持。

可读演示位于工作区 `artifacts/demo-final/`，包括 `review.html`、`case.json`、Markdown 和完整本地调用记录。浏览器工具拒绝 `file:` URL，因此未完成浏览器像素检查；未使用其他浏览器路径绕过该策略。HTML 的内容转义与条件保留已通过程序测试。运行数据不进入分发 ZIP，可用 `python -m parrhesia demo --output NEW_DIRECTORY` 重新生成。

## 未建立的证据

- Grok 对实际文本执行两次干净上下文审查和最终裁决的完整模型过程，尚未验收。
- 过度防御、理想化与空泛中立的实际改善幅度，尚未测量；没有用户收益或科学有效性结论。
- 内核不会证明模型阅读过全部资料、来源真实、代码确实执行、文献支持主张、预注册时间真实或用户身份真实。
- 商店安装、所有兼容客户端、非 Windows 原生宿主和所有文件系统未实测。原子导出使用硬链接，需要文件系统支持；失败会保留待恢复的报告，不会改用覆盖写入。

下一阶段的对照评价见 [评价方案](../evaluation-plan.md)，须先批准材料、数据去向、模型与费用计划。当前交付不依赖这些未执行的评价才能成为可用的试用插件，但不能据此升级效果主张。

## 外部工具与费用记录

AgentMuxer 仅执行免费 `search_offerings`，查询围绕官方插件文档与网页检索能力；无 `call_offering`、无付费 invocation、无待结算预留。目录付费支出为 $0。实际贡献是完成能力发现与工具选择，未借此产生内容或付费结果。

公开规范使用已有网页工具与官方站点，schema 来源、抓取时间和内容摘要保存在 `docs/schemas/agent-plugins-1.0.0/sources.json`。Grok 仅运行本地 CLI 的发现和诊断。未调用真实模型 API、未外发研究材料、未更改日常用户配置。当前对话本身的账户使用量不计作已核算的插件运行费用。
