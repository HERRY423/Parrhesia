## 已实现的变化

第一轮缩短了工具定义和规则入口，但契约调用仍默认返回整份文档。本轮增加可选的目录和章节读取，服务启动提示及生成规则改为先看目录，再读所需章节；旧的无参数调用保持原来的四字段全文返回。没有增加 MCP 工具数量或第三方运行时依赖。

| 项目 | 本轮基线 / 全文 | 修改后 / 选择性读取 | 说明 |
|---|---:|---:|---|
| 25 个工具定义 | 70,469 B | 68,547 B | 紧凑 JSON UTF-8，减少 2.7% |
| 契约首次读取 | 全文 76,985 B | 目录 3,449 B | 新目录入口减少 95.5% 的契约文本 |
| scaffold_claim 章节 | 全文 76,985 B | 章节 2,112 B | 不包含其他章节，明确标记非全文 |

契约行的比较使用本轮当前文档的全文与选读文本，按 LF 换行的 UTF-8 计数；并非前后文档大小对比，也不是 token、整个 MCP 响应或用户延迟测量。工具定义相对第一轮最初的 137,182 B 紧凑基线累计减少约 50.0%。

选读使用原文完整章节，不生成摘要或截断内容。返回 selection 元数据标明源文本指纹、来源/返回字节数、是否完整文档以及摘录行号；父章节包含其子章节。目录解析排除代码围栏内的假标题，并为重复标题生成不同 ID。调用方可用 expected_sha256 拒绝混用两个文档版本；未知章节和文档变化返回明确错误及修复提示，不默默替换成其他内容。

工具输入继续用具名 `$defs/$ref` 复用重复的类型、等级、判定枚举及 ID 列表。除 contract 新增可选参数与返回元数据外，其他 24 个工具的输入 schema 展开后与本轮保存基线完全相同，24 个 outputSchema 也完全相同。全部既有工作流动作的参数和运行时门控保持不变。

## 使用与边界

先调用 `parrhesia_contract`，参数 `{"section":"index"}`。从目录取得章节 ID 后，例如调用 `{"section":"scaffold_claim","expected_sha256":"目录返回的实际指纹"}`。不要把这个说明中的占位文字当实际指纹。若安装中的工具 schema 尚无 section 参数，使用原来的无参数全文调用。

结论限于 `engineering × test_passed`：选读路径的实际文本载荷减少、标准验证器和本地服务行为受检。原生宿主对新 schema 的接收、真实模型遵从率和用户效率仍为 NOT_RUN。下一步是在目标宿主加载同一构建后验证目录→章节→台账预检；若宿主不支持引用或选读接口，使用已有 workflow/全文回退并修复相应适配，不把本地测试外推为宿主验收。
